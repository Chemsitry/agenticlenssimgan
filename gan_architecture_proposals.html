Simulation-aware GAN design notes

Simple GAN architectures for adapting the v3 lens simulator to real JWST images

Written after reading the current agenticlenssim simulator and the older lenssim/gan attempt. The goal is not to replace the physics; it is to make the simulated images live in the same parameter and observational distribution as real JWST cutouts while preserving the lensing signal.

Bottom Line

Start with a parameter-calibrated simulator, followed by a small residual SimGAN. The biggest risk is not that SimGAN is a bad idea. The bigger risk is that simulate_v3.py gives the discriminator easy shortcuts before the GAN has a chance to learn anything useful.

The clearest example is lens position. In the current v3 code, both the lens mass and lens light are placed at (0, 0), so simulated lenses are almost always centered. If real JWST cutouts are not centered in the same way, the discriminator can win by asking a very boring question: is the main lens exactly in the middle? That is a simulator-parameter problem, not an image-texture problem.

The new adversarial question should therefore be two-stage: are the lens/source/crop parameters realistic, and after rendering, do the local multi-band image patches look like JWST data without damaging the arcs?

Recommended first run

Add and save sampled simulator parameters first: lens_center_x, lens_center_y, source_center_x, source_center_y, crop offset, shear, ellipticity, and arc/lens flux ratio. Then train a 4-band residual SimGAN as a refinement layer.

What the Current v3 Simulator Already Does Well

It is multi-band

The current pipeline renders F115W, F150W, F277W, and F444W on a common 0.03 arcsec/pixel grid. This matters because JWST realism is not only morphology; it is also color, dropout behavior, and lens-source contrast across bands.

It uses real survey structure

prep_mosaic.py extracts spatially matched COSMOS-Web backgrounds and empirical PSFs. prep_sources.py and prep_lenses.py can replace smooth Sersic profiles with real galaxy stamps. A GAN should not spend its capacity relearning what this preprocessing already gives us.

It has physics labels

simulate_v3.py saves labels and parameters such as lensed.npy, theta_Es.npy, z_lens.npy, z_source.npy, and masses.npy. More importantly, it saves sources_*.npy, which can act like a segmentation map for the lensed arcs.

Key implication for ML

The GAN should be split into two jobs. First, use a parameter-calibration step so the simulator draws realistic lens positions, source positions, crop offsets, brightness ratios, and shapes. Second, use a residual SimGAN as a domain-adaptation layer for observational details like noise, PSF texture, and small color mismatches.

The Parameter Problem

A GAN has two neural networks. The generator tries to produce images that look real. The discriminator tries to tell real images from generated images. Training works only if the discriminator has to learn meaningful differences.

A shortcut is an easy rule that solves the training game without learning the science. For example, if every simulated lens is centered but real cutouts have galaxies all over the stamp, then the discriminator can ignore arcs, colors, redshifts, and lensing morphology. It can simply look for a centered bright galaxy.

This is why an image-only SimGAN is not enough. A residual refiner can change texture and small pixel-level style, but it is deliberately discouraged from moving the lens or arcs. So if the simulator places the lens in the wrong part of the image, the refiner is designed not to fix that.

Beginner translation

Imagine fake product photos always place the object exactly in the center, while real photos are cropped naturally. A model can learn "center means fake" instead of learning what the object looks like. Your lens simulation has the same kind of risk.

Parameter Current v3 behavior Why it matters for a GAN Recommended change
Lens mass center center_x=0, center_y=0 Defines where the lensing deflection happens. If always centered, D gets a free clue. Sample lens_center_x/y from a realistic crop-offset distribution.
Lens light center center_x=0, center_y=0 The bright galaxy appears in the same place every time. Tie it to the mass center, with a tiny optional mass-light offset.
Source center Sampled around the fixed origin The source position is physically relative to the lens, not to the image stamp. Sample source offset relative to lens_center_x/y.
Image crop Implicitly centered on the lens system Real cutouts may be centered on candidates, catalog objects, or arbitrary sky positions. Match the real-data crop rule, or randomize crop offsets and save them.
Metadata Saves redshifts, mass, theta_E, and label A parameter-aware model cannot learn/check parameters that are not saved. Save centers, shear, ellipticity, flux ratios, stamp IDs, and crop offsets.
Important nuance

Centering is not automatically wrong. If the real target set is also cropped around known lens candidates, then centered simulations can be appropriate. The key rule is distribution matching: simulated cutouts and real cutouts should be centered, offset, masked, and scaled in the same way.

What Went Wrong in the Older GAN

Failure mode 1: easy discriminator shortcuts

The old discriminator returned one scalar for the whole 125x125 image. It could win by spotting global differences: centered lens galaxy versus off-center field galaxy, smooth lens light versus clumpy galaxy, or normalization artifacts.

Failure mode 2: target distribution mismatch

A generic JWST or VELA galaxy cutout is not the same distribution as a real strong-lens cutout. If the real set mostly contains ordinary galaxies, the discriminator can learn that arcs and massive central lenses are fake.

Failure mode 3: per-image min-max scaling

Normalizing every stamp independently to [0, 1] erases real flux, sky RMS, color, and surface-brightness information. It also gives the refiner no consistent physical scale to learn.

Updated diagnosis

The old GAN architecture was not the only issue. The simulator and real-data selection must also agree on basic parameters such as where the target galaxy sits in the cutout. A local PatchGAN makes the shortcut harder, but it does not remove the shortcut if every simulated system is generated with the same global geometry.

Old choice Why it hurt Replacement in the proposals below
Single-band F115W training JWST realism has strong multi-band color and dropout structure. Train with all four v3 channels, or at least RGB plus the blue short-wave average.
Scalar full-image discriminator D can classify using trivial global cues and starves G of useful gradient. Use local PatchGAN / crop discriminators, optionally with a weak global head.
BCE + sigmoid GAN loss Once D is confident, gradients saturate. Use WGAN-GP, hinge loss, or least-squares GAN. Add spectral norm or gradient penalty.
Refiner output forced through sigmoid It changes the image scale and can create edge artifacts. Use x_ref = x_sim + alpha * tanh(delta) with reflection padding.
Only generic pixel preservation The loss does not know which pixels carry the lensing signal. Use sources_*.npy to weight preservation on arcs and arc colors.

Architecture Proposals

Start here

A. Parameter-Calibrated Simulator + Residual SimGAN

This is the architecture I would now recommend first. It keeps the simulator in charge of the physics, but it stops treating simulator parameters as fixed background assumptions. The generator is not only an image refiner; it also proposes or adjusts the parameters that control where the lens appears, where the source sits relative to the lens, how bright the arc is, and how the cutout is cropped.

An MLP is just a small neural network for numbers instead of images. Here, it would output a short list of simulator settings. A PatchGAN is a discriminator that judges many small image patches instead of giving one score for the whole image; this makes it focus more on local JWST texture and less on one global clue.

Parameter generator Small MLP that outputs lens center, source offset, crop offset, shear, ellipticity, and flux-ratio adjustments.
Physics renderer simulate_v3.py / lenstronomy renders the actual lensing image from those parameters.
Image refiner Small residual SimGAN changes only observational style after rendering.
Discriminator PatchGAN plus a weak global head used as a shortcut detector. 
p = P(z_noise, optional_context)
x_sim, arc_map = simulate_v3(p)
x_ref = x_sim + alpha * tanh(R(x_sim, arc_map, p))

D asks:
  1. do local patches look like JWST?
  2. do global/crop statistics look real?

p means "parameters." For this project, examples are lens_center_x, lens_center_y, source_offset, theta_E, shear, ellipticity, and arc/lens flux ratio.

Why this matches your concern

If the discriminator is winning because all simulated lenses are centered, the generator must be allowed to change centering. A pure residual SimGAN is intentionally too weak to move the lens. This architecture gives the model a physics-aware knob for geometry and a separate image-refinement knob for JWST style.

Use after parameter audit

B. Multi-Band Residual SimGAN with Patch Discriminator

This is the direct successor to the old SimGAN idea, but adapted to the v3 simulator. The generator is a small residual image-to-image network. It sees a simulated 4-band image and outputs a small 4-band correction. The discriminator judges local patches rather than one whole-image score. This is still useful, but only after the simulator's parameter distribution is close to the real cutout distribution.

Input x_sim: B x 4 x 125 x 125, fixed physical/asinh scaling.
Generator Reflection pad -> conv(4, 64) -> 4 residual blocks -> conv(64, 4) -> tanh residual.
Output x_ref = x_sim + alpha * tanh(G(x_sim, arc_mask)), with alpha small.
Discriminator 70x70-ish PatchGAN over 4-band patches, no final sigmoid if using hinge or WGAN-GP.
Real data Prefer real lens candidates or central-galaxy-matched JWST cutouts in the same four bands. 
L_G =
    L_adv_patch
  + lambda_img   * SmoothL1(x_ref, x_sim)
  + lambda_arc   * SmoothL1(M_arc * x_ref, M_arc * x_sim)
  + lambda_color * color_ratio_loss(x_ref, x_sim, M_arc)
  + lambda_flux  * aperture_flux_loss(x_ref, x_sim)

The arc mask M_arc comes from sources_*.npy. This is the crucial physics constraint: the network may make the image look more JWST-like, but it pays a large penalty for moving, dimming, or recoloring the arc.

Why this should work better than the old GAN

Local D focuses on noise texture, PSF wings, small galaxy substructure, and color covariance. Residual G starts near the identity map. Arc-weighted preservation prevents the network from solving the game by making lens images look like ordinary galaxies. But this does not solve a global parameter mismatch such as every simulated lens being centered; that has to be handled before or alongside this refiner.

Very safe first diagnostic

C. Nuisance-Only Residual GAN

This version deliberately prevents the GAN from changing the astrophysical scene. It can only learn detector/background/PSF-like residuals. Use this as the first NERSC sanity check if you are worried about a full-image GAN destroying arcs.

Architecture

  • G_noise: 3 to 5 convolutional layers, 32 or 64 channels, residual output.
  • D_highpass: sees random 32x32 or 48x48 high-pass-filtered patches.
  • Optional Fourier head: match the local noise power spectrum per band.
  • Mask out arc and bright lens cores from the adversarial patches.

Training target

Use real JWST sky/galaxy cutouts for detector texture, but do not ask D to judge the entire semantic image. D should see only nuisance residuals: local sky covariance, drizzle-correlated noise, faint unresolved background, and PSF-ish texture. 

x_ref = x_sim + G_noise(highpass_context)
D sees highpass(x_ref) versus highpass(real_jwst)
What it will not fix

It will not learn large-scale lens-galaxy morphology or realistic source populations. That is fine. Its job is to prove the data loader, normalization, and GAN loss are stable before you allow the generator to touch visible structure.

Use after B is stable

D. Masked CycleGAN-Lite

CycleGAN is useful when you have unpaired data: a pile of simulations and a pile of real JWST cutouts, but no one-to-one pairs. It learns two maps, simulation-to-real and real-to-simulation, and forces a round trip to reconstruct the input.

Sim image x
to
G: sim to real style
to
F(G(x)) should recover x

Keep it light

  • Use the same residual image refiner as Proposal B for G.
  • Use an even smaller residual generator for F.
  • Use PatchGAN discriminators D_real and D_sim.
  • Strong identity loss: real images passed through G should stay real.
L =
    L_adv_real(G, D_real)
  + L_adv_sim(F, D_sim)
  + lambda_cycle * |F(G(x_sim)) - x_sim|
  + lambda_id    * |G(x_real) - x_real|
  + lambda_arc   * |M_arc * (G(x_sim) - x_sim)|
Main risk

Cycle consistency is a weak physical constraint. The network can sometimes hide information in imperceptible patterns to satisfy the cycle loss. Use this only after the simpler residual SimGAN has taught you what a stable run looks like.

Good second-generation model

E. Physics-Conditioned Residual GAN

The simulator knows physical parameters that a plain image-to-image GAN ignores. This architecture gives the refiner a small condition vector so it can learn that, for example, high-redshift sources, small Einstein radii, and red lens galaxies should receive different corrections.

Condition vector

Start with [theta_E, z_lens, z_source, lens_center_x, lens_center_y, source_offset, arc_lens_ratio, lensed], normalized to roughly order one. Feed it through a tiny MLP and use FiLM-style scale/shift inside residual blocks. 

h = ResBlock(h)
gamma, beta = MLP(params)
h = gamma[:, :, None, None] * h + beta[:, :, None, None]

Why it helps

A correction appropriate for a bright, low-z, large-theta_E system may be wrong for a tiny high-z arc. Conditioning gives the model a controlled way to vary its style corrections without inventing new lens geometry.

Keep the discriminator mostly unconditioned unless you have real lens labels. Real JWST images will not automatically have theta_E and z_source, so conditioning belongs primarily in the generator.

Useful if you save more simulator components

F. Paired Simulator-Component GAN

This is a pix2pix-like architecture, but the pairs come from the simulator rather than from real data. Modify v3 to save clean components: lens light, source arcs, background, clean no-background image, and final noisy image. Train a U-Net-like composer on those simulated pairs, then add a weak real-JWST adversarial loss.

Part Design Purpose
Generator Small U-Net, input channels = lens-only, source-only, background, masks, parameters. Learns observation/composition while keeping components visible.
Paired loss L1/Huber to the simulator's final image. Prevents unconstrained GAN behavior.
Adversarial loss PatchGAN against real JWST patches. Pushes the synthetic observation model toward real data.
Why this is attractive

It uses the simulator's natural decomposition instead of asking a black box to discover it. This is often easier to debug for a physics project because you can inspect which component caused a bad output.

Data Recipe for Real JWST Images

Use fixed physical normalization

Do not repeat the old per-image min-max normalization. Keep images in a consistent unit system per band, then apply a fixed transform such as: 

y_band = asinh((image_band - sky_median_band) / (k * sky_sigma_band))

Save sky_median_band, sky_sigma_band, and k. The inverse transform should be possible for display and flux checks.

Match the target distribution to the adversarial question

If D sees whole images, real targets should be real lens candidates or at least cutouts matched to a central red galaxy. If D sees only local nuisance residuals, generic real JWST sky patches are acceptable.

Step Recommendation Reason
Band alignment Cut matched 4-band stamps in the same order as v3: F115W, F150W, F277W, F444W. The GAN should learn cross-band covariance, not independent grayscale tricks.
Stamp selection Reject edges, bad WHT/coverage, NaNs, saturation, and severe artifacts. D will happily learn data-quality shortcuts.
Cutout centering Use the same crop rule for simulations and real data: centered on candidate, centered on catalog galaxy, or randomized sky crop. If fake and real cutouts use different centering rules, D can win from position alone.
Simulator parameters Save lens/source centers, crop offsets, shear, ellipticity, flux ratios, and stamp IDs. You cannot debug or condition on parameters that were never saved.
Real/full-image targets Use lens candidates or central-galaxy-matched cutouts. Otherwise D learns that ordinary galaxies are real and lenses are fake.
Train/val split Split by mosaic tile or sky region, not by random cutout. Prevents memorizing local background texture.
Simulator data Stack images_*.npy; build arc masks from sources_*.npy. The source-only arrays are the built-in physics-preservation handle.
Scaling check Plot pixel histograms and per-band flux percentiles before training. Most GAN "mystery failures" start as boring normalization bugs.

Implementation Skeleton

This is intentionally small. The most important details are: first fix or learn the simulator parameters, then use residual output, reflection padding, local discrimination, and arc-weighted preservation for image refinement. 

# tensors
# parameter-aware simulation step
p = sample_or_generate_parameters()
p["lens_center_x"], p["lens_center_y"] = sample_crop_matched_lens_center()
p["source_center_x"] = p["lens_center_x"] + p["source_offset"] * cos(p["source_angle"])
p["source_center_y"] = p["lens_center_y"] + p["source_offset"] * sin(p["source_angle"])

x_sim, source_only = simulate_v3_render(p)

# tensors
x = stack_bands(x_sim["F115W"], x_sim["F150W"], x_sim["F277W"], x_sim["F444W"])
s = stack_bands(source_only["F115W"], source_only["F150W"], source_only["F277W"], source_only["F444W"])

# simple arc mask, shape B x 1 x H x W
m_arc = (abs(s).sum(dim=1, keepdim=True) > tau).float()

# generator input can include the mask as an extra channel
delta = G(torch.cat([x, m_arc], dim=1))
x_ref = x + alpha * torch.tanh(delta)

# discriminator update
loss_D = D_loss(D(real_jwst), D(x_ref.detach()))

# generator update
loss_pres = smooth_l1((x_ref - x) * (1 + arc_weight * m_arc), 0)
loss_G = adv_loss(D(x_ref)) + lambda_pres * loss_pres
loss_G.backward()
Generator size 4 to 6 residual blocks, 32 or 64 channels. Bigger is not the first fix.
Discriminator size PatchGAN with spectral norm or WGAN-GP. Random crops help a lot.
First hyperparameters alpha=0.05 to 0.15, lambda_pres=10 to 100, arc_weight=20.

How to Know Whether It Worked

Arc preservation Source-mask weighted L1, arc aperture flux ratio, arc color ratios, and radial location of bright source pixels. These should barely move.
JWST texture Pixel histograms, sky RMS, 2D power spectra, local noise covariance, and PSF-wing statistics should move toward real cutouts.
GAN health D should not go perfect in the first epoch. With WGAN-GP, critic scores should remain smooth and interpretable, not flatlined.
Science utility Train a lens classifier on raw sims versus refined sims, then test on held-out real candidates or visually curated examples.
A good qualitative panel

For each example, show: raw simulation, refined simulation, difference image, source-only arc map, real JWST comparison batch, and RGB composite. If you cannot see the arc in the source-only row after refinement, stop and increase the preservation loss.

Shortcut audit

Before trusting any GAN result, compare simple histograms for simulated versus real cutouts: brightest-galaxy position, lens/candidate center, radial flux profile, arc radius, and background RMS. If a one-line feature like "distance from image center" separates real from fake, the simulator parameters still need work.

Practical NERSC Roadmap

Stage Run Success criterion
0. Data + parameter audit Load 256 simulated and 256 real 4-band cutouts. Plot RGBs, masks, lens-center histograms, crop offsets, radial profiles, and pixel histograms. No NaNs, sensible fixed scaling, matching band order, and no obvious "center means fake" shortcut.
1. Parameter-calibrated sims Add sampled lens/source centers and crop offsets to simulate_v3.py. Save them in output arrays and metadata. Simulated and real cutouts have comparable position/crop statistics.
2. Nuisance GAN Proposal C, 1 GPU, 1 to 2 hours, small crops. Stable D, realistic noise/residual texture, zero arc damage.
3. Residual SimGAN Proposal B, 4-band 125x125, batch 16 or 32, WGAN-GP or hinge. Refined images visibly closer to JWST while arc-preservation metrics stay tight.
4. Matched real targets Repeat the parameter-calibrated + residual setup using central-galaxy/lens-candidate real cutouts. D no longer wins from semantic shortcuts; refined images look lens-like and JWST-like.
5. Conditional or Cycle model Try Proposal D or E only after Stage 3 is stable. Improves parameter, texture, and arc-preservation metrics, not merely prettier images.

Final Ranking

Rank Architecture Why
1 Parameter-Calibrated Simulator + Residual SimGAN Best match to the actual failure mode: it can change lens/crop parameters and then refine image style.
2 Multi-band Residual SimGAN with PatchGAN Good image refiner once simulator parameters are already close to real cutouts.
3 Nuisance-Only Residual GAN Safest diagnostic. Great for proving the real-data loader and loss are sane.
4 Physics-Conditioned Residual GAN Natural upgrade once the basic refiner works and extra parameters are saved.
5 Paired Simulator-Component GAN Very interpretable, but requires saving more simulator components.
6 Masked CycleGAN-Lite Powerful for unpaired data, but more ways to fool itself. Use later.
