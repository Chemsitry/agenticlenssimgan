OVERVIEW
--------
This document summarizes the steps taken to download, process, and integrate
real James Webb Space Telescope (JWST) imaging data into a gravitational lens
simulation pipeline. The goal is to replace synthetic backgrounds in an
existing simulation notebook with real JWST sky patches, producing more
realistic training data for a gravitational lens classifier.


--------------------------------------------------------------------------------
STEP 1: DATA ACQUISITION
--------------------------------------------------------------------------------

Source:
  MAST (Mikulski Archive for Space Telescopes) — program jw01810, observation 2,
  target 2. Downloaded as a single zip archive: MAST_2026-02-26T2313.zip (2.9 GB).

Extracted contents — 7 JWST NIRCam mosaics (Level 3, i2d pipeline products):

  Filter   Wavelength   Pixel Scale   Image Size        File Size
  -------  -----------  ------------  ----------------  ---------
  F090W    ~0.9 µm      0.031"/pix    9887 × 4390 px    1.1 GB
  F115W    ~1.15 µm     0.031"/pix    9887 × 4390 px    1.1 GB
  F150W    ~1.5 µm      0.031"/pix    9887 × 4390 px    1.1 GB
  F200W    ~2.0 µm      0.031"/pix    9887 × 4390 px    1.1 GB
  F277W    ~2.77 µm     0.063"/pix    4384 × 9883 px    275 MB
  F356W    ~3.56 µm     0.063"/pix    4384 × 9883 px    275 MB
  F444W    ~4.44 µm     0.063"/pix    4384 × 9883 px    275 MB

  Total extracted size: ~5.4 GB
  Flux units: MJy/sr (native JWST pipeline output)
  Pixel area: PIXAR_SR = 2.292e-14 sr/pix (from FITS header keyword PIXAR_SR)

FITS structure (each file, example F200W):
  HDU 0  PRIMARY       — 271 header keywords, no data
  HDU 1  SCI           — Science image (float32), 9887 × 4390 px
  HDU 2  ERR           — Total error array
  HDU 3  CON           — Context map (which exposures contributed)
  HDU 4  WHT           — Weight map
  HDU 5  VAR_POISSON   — Poisson noise variance
  HDU 6  VAR_RNOISE    — Read noise variance
  HDU 7  VAR_FLAT      — Flat field variance
  HDU 8  HDRTAB        — Per-exposure header table
  HDU 9  ASDF          — Calibration metadata blob

Rationale for F115W:
  The existing simulation notebook was built around JWST NIRCam F115W (matching
  the Williams et al. 2018 GOODS-S simulated image and VELA galaxy templates
  in that filter). All preprocessing focused on the F115W mosaic.


--------------------------------------------------------------------------------
STEP 2: BACKGROUND CHARACTERIZATION
--------------------------------------------------------------------------------

Tool: prep_jwst.py (custom preprocessing script)

  a) Sky background measurement
     - Loaded the F115W SCI extension into memory
     - Built a validity mask: pixels where data is finite AND weight > 0
     - Applied sigma-clipped statistics (σ=3, 5 iterations) on a 1-in-100
       subsample of valid pixels to measure the sky level

     Results:
       background_mean   = 0.294924 MJy/sr
       background_rms    = 0.008549 MJy/sr
       (saved to prepped/background_mean.npy and prepped/background_rms.npy)

  b) Unit conversion derivation
     The simulation notebook works in internal flux units where:
       1 simulation unit = 1/sum_to_flux nJy = 1/6.502 nJy ≈ 0.154 nJy/pixel

     Conversion from real JWST MJy/sr to simulation units:
       nJy/pixel = MJy/sr × PIXAR_SR × 10^15
       sim_units = nJy/pixel × sum_to_flux
       → scale factor = PIXAR_SR × 10^15 × sum_to_flux ≈ 149.0

     This factor is applied when the real backgrounds are loaded in the
     simulation notebook.


--------------------------------------------------------------------------------
STEP 3: REAL BACKGROUND PATCH EXTRACTION
--------------------------------------------------------------------------------

  Method:
    - Randomly sampled 125 × 125 pixel patch centers from the F115W mosaic
    - Required ALL pixels in the patch to be valid (finite, weight > 0)
      — no source masking, so patches include real faint galaxies
    - Subtracted background_mean from each patch (zero-mean normalization)
    - Collected 5,000 patches in 7,199 random attempts

  Why include faint galaxies (no source masking):
    The original sim_background() function was designed to render environmental
    galaxies from a mock catalog around a random field galaxy. Real JWST patches
    naturally contain real faint background galaxies, making them a more realistic
    and direct replacement for the rendered mock backgrounds.

  Output: prepped/real_backgrounds.npy
    Shape: (5000, 125, 125), dtype: float32, size: 298 MB


--------------------------------------------------------------------------------
STEP 4: EMPIRICAL PSF EXTRACTION
--------------------------------------------------------------------------------

  Method (pure numpy, no scipy required):
    - Identified all pixels above a 20-sigma bright threshold
    - For each bright pixel, checked if it was a local maximum in a 5×5 window
    - Enforced isolation: no other bright pixel within 31 pixels (half stamp size)
    - Required compactness: ≥50% of flux within r < 10 px of center
      (selects unresolved point sources / stars, rejects extended galaxies)
    - Extracted 63 × 63 pixel stamps around each candidate
    - Subtracted sky background and normalized each stamp to unit flux sum
    - Collected 200 PSF star stamps

  Output: prepped/psf_stars.npy
    Shape: (200, 63, 63), dtype: float32, size: 3.2 MB

  Note: PSF integration into lenstronomy (replacing the Gaussian PSF currently
  used in the simulation notebook) is a planned future step.


--------------------------------------------------------------------------------
STEP 5: SIMULATION NOTEBOOK INTEGRATION
--------------------------------------------------------------------------------

  The existing simulation notebook (simulations (1).ipynb) was modified to
  replace the sim_background() function with real JWST backgrounds.

  Changes made:

  a) New cell inserted (after kwargs setup cell):
     - Loads prepped/real_backgrounds.npy
     - Applies unit conversion scale factor (≈149.0)
     - Defines get_real_background() as a drop-in replacement for sim_background()

       Code:
         real_bgs     = np.load(REAL_BG_PATH)
         PIXAR_SR     = 2.29232933396454e-14
         mjysr_to_sim = PIXAR_SR * 1e15 * sum_to_flux   # ≈ 149.0
         real_bgs_sim = (real_bgs * mjysr_to_sim).astype(np.float32)

         def get_real_background():
             return real_bgs_sim[_bg_rng.integers(len(real_bgs_sim))]

  b) Test visualization cell (cell-10):
     sim_background(exp_time=1200)  →  get_real_background()

  c) Main generation loop (cell-12):
     back_gals = sim_background(exp_time=exp_time)  →  get_real_background()

  Path note:
     REAL_BG_PATH is set to home + "JWST/prepped/real_backgrounds.npy"
     This must be updated to the correct path when running on the cluster.

STEP 6: STANDALONE TEST NOTEBOOK
--------------------------------------------------------------------------------

  File: test_generate.ipynb

  Purpose:
    A self-contained test notebook that generates 5 lensed + 5 non-lensed
    images without requiring NERSC cluster resources (no CosmoDC2, no VELA).

  Key design choices:

  a) No CosmoDC2 catalog required:
     - Lens redshifts sampled from Uniform(0.1, 0.8)
     - Source redshifts sampled from truncated Normal(loc=1.5, scale=3)
     - Halo masses sampled from log-Uniform(10^13, 10^14.5 M_sun)
     - Ellipticities, Sérsic indices, radii sampled from matching distributions

  b) No VELA images required:
     - Both lens and source rendered as Sérsic ellipse profiles
       (equivalent to sersic_source=True in the original notebook)

  c) Lensed vs. non-lensed distinction (matching original notebook):
     - Non-lensed: lens galaxy light only, source amplitude set to 0
     - Lensed: lens galaxy light + lensed arcs (θE enforced in 0.5–1.5″ range)
     - Arc brightness boosted by scale_up = 10^Uniform(0,2) (random 1x–100x)

  d) Apple Silicon (M3) considerations:
     - numpy on macOS with Homebrew Python automatically uses Apple's Accelerate
       framework (vecLib BLAS) for matrix operations — no extra setup needed
     - Multiprocessing (mp.Pool) was attempted but does not work inside Jupyter
       on macOS (spawn-based pickling of notebook-defined functions fails)
     - Sequential execution used instead; 10 images complete in <1 second

  e) Environment:
     - System Homebrew Python 3.14 has a broken scipy installation that
       conflicts with numba, lenstronomy, and astropy.convolution
     - Solution: isolated virtual environment (.venv/) with clean installs of
       numpy, scipy, astropy, lenstronomy, matplotlib, jupyter, nbconvert
     - Notebooks must be run with .venv/bin/jupyter to use the clean environment

  Outputs saved to output/:
    images.npy        (10, 125, 125) — full simulated images
    image_source.npy  (10, 125, 125) — arc-only images (no lens light)
    lensed.npy        (10,)          — labels: 0 = non-lensed, 1 = lensed
    theta_Es.npy      (10,)          — Einstein radii in arcseconds
    z_lens.npy        (10,)          — lens redshifts
    z_source.npy      (10,)          — source redshifts
    masses.npy        (10,)          — halo masses in solar masses
    preview.png                      — 3-row visualization (see below)

  Visualization (output/preview.png) — 3 rows:
    Row 1: Non-lensed full images (√ stretch)
    Row 2: Lensed full images (√ stretch) — arcs present but faint under lens
    Row 3: Arc-only images (inferno colormap, linear) — arcs clearly visible

STEP 7: VISUAL VERIFICATION OF RESULTS
--------------------------------------------------------------------------------

  The test run confirmed:
    - Non-lensed images show smooth elliptical lens galaxies with no arc structure
    - Lensed images show the same lens galaxies with Einstein rings/arcs
    - Arc-only diagnostic images clearly show ring and arc morphologies at
      Einstein radii ranging from 0.51″ to 1.06″
    - Real JWST backgrounds are present in all images (real noise + faint galaxies)

  Known limitation:
    The arcs are faint relative to the lens galaxy light in the full images.
    This is physically realistic — gravitational lens arcs are genuinely
    challenging to detect against the bright lens galaxy, which is why a
    machine learning classifier is needed.

--------------------------------------------------------------------------------
FUTURE STEPS / KNOWN ISSUES
--------------------------------------------------------------------------------

  1. Unit scaling validation:
     The scale factor (≈149.0) converting MJy/sr to simulation flux units was
     derived from FITS header keywords. The sum_to_flux = 6.502 calibration
     constant in the simulation notebook was derived from the Williams et al.
     (2018) synthetic GOODS-S dataset, not from the jw01810 data. This should
     be re-validated before large-scale training data generation.

  2. PSF integration:
     psf_stars.npy contains 200 empirical PSF stamps extracted from the real
     F115W mosaic. These should replace the Gaussian PSF (fwhm=0.03") currently
     used in the simulation notebook. lenstronomy supports 'PIXEL' PSF type
     which accepts an empirical kernel array.

  3. Multi-filter extension:
     All 7 filters (F090W–F444W) are available. Extending the simulation to
     produce multi-band image stacks would improve classifier performance.

  4. Scale to full training set:
     The original notebook was designed to generate ~40,000 images on NERSC.
     The modified notebook (with get_real_background()) is ready to be run
     at scale on the cluster once REAL_BG_PATH is updated to the cluster path.

  5. VELA + CosmoDC2 integration:
     The test notebook uses simplified Sérsic profiles. The full pipeline on
     the cluster should continue using VELA simulated galaxy images as sources
     and CosmoDC2 for lens halo parameters, as in the original notebook.

STEP 8: SIMULATE_V2 — IMPROVED SINGLE-BAND PIPELINE (March 2026)
--------------------------------------------------------------------------------

  File: simulate_v2.ipynb (+ run_simulate_v2.py extracted script)

  Improvements over test_generate.ipynb:

  a) Empirical PSF:
     - Replaced Gaussian PSF (FWHM=0.06") with median stack of 174 real star
       stamps (63x63 px) from jw01810 F115W
     - Used as lenstronomy 'PIXEL' PSF with supersampling_factor=3
     - Run `python3 build_psf.py` first to generate prepped/psf_median.npy

  b) SIE + SHEAR lens model:
     - Replaced SIS (perfectly symmetric) with SIE + external shear
     - Produces realistic asymmetric arcs, partial arcs, off-axis images

  c) SLACS-calibrated parameter distributions:
     - z_lens   ~ TruncNorm(0.3, 0.15, [0.05, 0.90])
     - sigma_v  ~ TruncNorm(215, 50, [100, 400]) km/s (drives theta_E)
     - z_source ~ TruncNorm(1.5, 0.8, [0.6, 3.0])
     - log M_halo ~ Uniform(11.5, 13.0) — galaxy-scale, NOT cluster-scale
       (old range 13.0–14.5 was cluster territory, lens light drowned arcs)

  d) Poisson shot noise on simulated components:
     - Conversion: sim_units -> electrons via PHOTMJSR, XPOSURE, GAIN
     - SIM_TO_ELEC ≈ 48.7 e-/sim_unit (F115W, jw01810)
     - np.random.poisson(electrons) applied per pixel before adding background
     - Real JWST background (which has its own noise) added on top

  e) Arc/lens brightness floor:
     - ARC_LENS_MIN_RATIO = 1e-2 (arc total flux >= 1% of lens total flux)
     - Prevents completely undetectable arcs

  f) Preview display:
     - Switched from sqrt stretch to asinh stretch (AsinhNorm)
     - Compresses bright lens core, reveals faint arcs
     - 6-row preview: linear + asinh + lens-subtracted + arc-only

  Arc visibility note:
     The lens galaxy peak pixel is typically 100–500x brighter than the arc
     peak pixel. This is physically realistic for SLACS-like systems. The arcs
     are present in the data but invisible in linear display — exactly why ML
     models are needed for lens finding. The lens-subtracted view (row 5)
     confirms arcs are present with correct morphology.

     - Source galaxy (star-forming): blue SED, relatively brighter at shorter λ
       F115W=1.0, F150W~0.85, F277W~0.4, F444W~0.25 (z-dependent)
     - Calibrated in F115W, then scaled per band using color ratios

     - SIM_TO_ELEC computed per band using each band's PHOTMJSR and XPOSURE

STEP 10: RGB COLOR FIX — PIXEL SOLID ANGLE NORMALIZATION (March 2026)
--------------------------------------------------------------------------------

  Problem:
    RGB composite images (R=F277W, G=F150W, B=F115W) showed everything
    appearing red — including arc-only rows that should be blue. The professor
    noted: "arcs generally have a different color from the lenses — typically
    the arcs are bluer."

  Root cause — pixel solid angle mismatch:
    LW channel pixels (F277W, F444W at 0.063"/pix) have ~4x the solid angle
    of SW channel pixels (F115W, F150W at 0.031"/pix):

      PIXAR_SR_F277W = 9.30e-14 sr/pix
      PIXAR_SR_F115W = 2.24e-14 sr/pix   (ratio ~ 4.15x)

    When building the RGB, the F277W image (63x63) was upsampled to 125x125
    using scipy.ndimage.zoom, but per-pixel values were NOT normalized for
    the different pixel solid angles. Each F277W pixel covers ~4x the sky
    area, so its per-pixel surface brightness is ~4x higher for the same
    physical flux density. This inflated the red channel in the RGB.

  Fix (simulate_multiband.py, lines 533-555):
    Before building the RGB composite, divide each band's image by its
    mjysr_to_sim factor (proportional to PIXAR_SR), converting all bands to
    the same MJy/sr surface brightness units:

      rgb = make_rgb(
          images_F277W / BAND_CONFIG['F277W']['mjysr_to_sim'],   # R
          images_F150W / BAND_CONFIG['F150W']['mjysr_to_sim'],   # G
          images_F115W / BAND_CONFIG['F115W']['mjysr_to_sim'],   # B
      )

    mjysr_to_sim values used:
      F115W: 145.6    F150W: 149.0    F277W: 604.7    F444W: 606.6

    Dividing F277W by 604.7 vs F115W by 145.6 removes the ~4x solid angle
    bias, so the RGB color ratios now correctly reflect the SED color ratios.

  Color-preserving RGB rendering (make_rgb function):
    1. Compute luminance L = R + G + B
    2. Apply asinh stretch to L (compresses dynamic range for display)
    3. Redistribute stretched luminance back to R/G/B channels preserving
       the original R:G:B ratio at each pixel
    Result: elliptical lenses appear red/orange, star-forming arcs appear
    blue/cyan — matching physical expectations for their stellar populations.

  Verified result:
    - preview.png row 5 (RGB lensed): lens galaxies appear warm/reddish-orange
    - preview.png row 6 (RGB arcs): arcs clearly appear blue/cyan
    - preview_same_brightness.png: when arcs are boosted to match lens peak
      brightness, the color contrast is unambiguous (blue arcs vs red lens)

  New file: make_same_brightness_preview.py
    Standalone script to regenerate preview_same_brightness.png from saved
    .npy arrays without re-running the full simulation.

STEP 11: v3 — COWLS-CALIBRATED PARAMETERS (March 2026)
--------------------------------------------------------------------------------

  Reference:
    Nightingale et al. 2025, MNRAS 543, 203-222
    "The COSMOS-Web Lens Survey (COWLS) I: discovery of >100 high redshift
    strong lenses in contiguous JWST imaging"

  The COWLS paper searched the same COSMOS-Web JWST data (program 1727,
  F115W/F150W/F277W/F444W) we use for backgrounds and PSFs. They found
  >100 strong lens candidates with properties that differ significantly
  from the SLACS sample that v2 was calibrated to.

  Key COWLS findings that drove parameter changes:
    - ~50% of lens galaxies above z=1, some beyond z=2
    - Source galaxies span z~0.1 to z~9 (epoch of reionization)
    - Einstein radii mostly below 1.0" (SLACS: typically above 0.8")
    - Lower stellar masses than SLACS (most log M* < 11, vs SLACS > 11)
    - Lens magnitudes F444W 16-22 AB (SLACS: 15-17 AB)
    - Same lens model: SIE + external shear

  a) Parameter changes (v2 -> v3):

     Parameter    v2 (SLACS)                        v3 (COWLS)
     ----------   --------------------------------  --------------------------------
     z_lens       TruncNorm(0.3, 0.15, [0.05,0.9])  TruncNorm(0.7, 0.4, [0.05,2.5])
     z_source     TruncNorm(1.5, 0.8, [0.6, 3.0])   TruncNorm(2.5, 1.5, [0.5, 7.0])
     sigma_v      TruncNorm(215, 50, [100, 400])     TruncNorm(180, 50, [80, 350])
     theta_E      filter [0.5, 1.5]"                  filter [0.2, 1.5]"
     log M_halo   U(11.5, 13.0)                       U(11.0, 13.0)
     SED source   linear z-scaling                     Lyman-break aware (dropout)

  b) Lyman-break aware source SED (starforming_color_ratios):
     - At z > ~3.5, Lyman break enters F115W -> flux drops to near-zero
     - At z > ~5, Lyman break enters F150W
     - At z > ~6.5, Lyman break reaches F277W
     - Produces realistic "HST-dark" red sources that COWLS reports at z > 4
     - Below the break: strong IGM absorption (flux ~ 0)
     - Above the break: blue UV slope (f_nu ~ lambda^-0.5)

  c) Results from 10 test images:
     Lensed sample statistics:
       z_lens:   0.25 - 0.97  (mean 0.61)    [v2 mean was ~0.3]
       z_source: 0.92 - 2.74  (mean 1.86)    [v2 mean was ~1.1]
       theta_E:  0.24 - 0.95  (mean 0.48)    [v2 mean was ~0.7]
     Example source SED at z=2.52:
       F115W=1.00  F150W=0.88  F277W=0.64  F444W=0.51

  d) File: simulate_v3.py
     Output directory: output/v3/
     Same structure as v2: per-band images, sources, labels, parameters
     Added: metadata.json with version info and all parameter distributions
     All v2 fixes preserved: RGB pixel solid angle normalization,
       color-preserving asinh stretch, per-band Poisson noise

  e) Version history:
     v1: test_generate.ipynb / simulate_v2.ipynb
         Single band (F115W), jw01810 data, Gaussian PSF, SIS lens model
     v2: simulate_multiband.py -> output/multiband/

STEP 12: DEEP MOSAIC UPGRADE — COSMOS-Web DR0.5 (March 2026)
--------------------------------------------------------------------------------

  Problem:
    v2/v3 images looked nothing like the real JWST images in COWLS paper
    Figure 5 (Nightingale et al. 2025, page 10). Root cause: we were using
    single-detector i2d files (2058x2058, 258s exposure) — individual short
    exposures from one detector chip. The COWLS team used the full coadded
    survey mosaics: 36000x30000 pixels, ~6184s effective exposure (24x deeper).

  Solution:
    Downloaded the full COSMOS-Web DR0.5 mosaics from the public data release
    at exchg.calet.org/cosmosweb-public/DR0.5/NIRCam/Jan23/.

  a) Data downloaded (raw_data/1727_mosaic/):

     Band    File Size  Pixel Scale  Image Size        Exposure
     ------  ---------  -----------  ----------------  --------
     F115W   ~48 GB     0.030"/pix   36000 x 30000     6184.4s
     F150W   ~48 GB     0.030"/pix   36000 x 30000     6184.4s
     F277W   ~32 GB     0.030"/pix   36000 x 30000     6184.4s
     F444W   ~32 GB     0.030"/pix   36000 x 30000     6184.4s

STEP 13: REALISTIC SOURCE MORPHOLOGY — INTERPOL GALAXY STAMPS (March 2026)
--------------------------------------------------------------------------------

  Problem:
    Simulated arcs used smooth Sersic ellipse profiles for the source galaxy.
    This produces clean, symmetric arcs that look visibly synthetic compared to
    real COWLS images (e.g., COWLS II Figure 1, Mahler et al. 2025, MNRAS 544,
    L8-L14), where arcs show complex structure: clumpy star-forming regions,
    spiral arms, irregular morphology, knots.

  Solution:
    Extract real galaxy stamps from the COSMOS-Web DR0.5 mosaics and use them
    as pixelated source light profiles via lenstronomy's INTERPOL model.

  a) Source extraction (prep_sources.py):
     - Detection: extended sources in F277W at 15-sigma above background
     - Extended source selection via concentration index:
       C = core_flux(r<5px) / total_flux(r<32px)
       Stars: C > 0.5 (compact PSF)
       Galaxies: C < 0.45 (spread-out light)
     - Found 17,634 extended source candidates in 36000x30000 mosaic
     - Selected 500 brightest isolated galaxies (STAMP_SIZE spacing)
     - Multi-band matched extraction: same pixel position in all 4 bands
     - Background-subtracted and normalized to sum=1 per band per stamp
     - Output: prepped_mosaic{_size}/sources/stamps_{band}.npy (500, 65, 65)
       ~34 MB total (8.4 MB per band)

  b) INTERPOL source model (simulate_v3.py):
     - lenstronomy's INTERPOL light profile: places a pixelated image in the
       source plane. The image is interpolated via RectBivariateSpline and
       ray-traced through the lens to produce the lensed image.
     - Parameters: image (2D array), amp, center_x, center_y, phi_G, scale
     - phi_G = continuous random rotation (0 to 2*pi)
     - Random horizontal flip for additional augmentation
     - Combined: effectively infinite unique source orientations from 500 stamps
     - Falls back to SERSIC_ELLIPSE if stamps not available (--sersic flag)
     - Amplitude calibration identical to Sersic: render with amp=1, measure
       total flux, rescale to desired flux. SED color ratios still applied
       per band for overall band-to-band color.

  c) Per-band morphology:
     Each band's stamp is extracted independently and normalized to sum=1.
     This preserves wavelength-dependent morphology: F115W shows UV-bright
     star-forming knots, F444W shows smoother stellar mass distribution.
     The SED color ratios (starforming_color_ratios) control the overall
     band-to-band flux ratio, while the intra-galaxy morphology comes from
     the real data.

  d) Known limitation — double PSF convolution:
     Extracted stamps include the JWST PSF. When used as source profiles,
     lenstronomy reconvolves the lensed image with the PSF. This effectively
     applies the PSF twice, mildly broadening arcs (~sqrt(2) in PSF sigma).
     For resolved galaxies (>5 pixels across), this is a modest effect.
     Future improvement: PSF deconvolution of stamps before normalization.

  e) Results:
     Arc morphology is dramatically improved — arcs now show complex structure
     (asymmetries, clumps, extended features) instead of smooth symmetric rings.
     Performance is comparable to Sersic (~0.09s/image at 224x224, ~0.03s at 125).

  Usage:
     .venv/bin/python3 prep_sources.py --size 224          # extract stamps
     .venv/bin/python3 simulate_v3.py --size 224           # INTERPOL sources
     .venv/bin/python3 simulate_v3.py --size 224 --sersic  # force Sersic

  UPGRADE 1: RGB RENDERING METHOD
  ────────────────────────────────
  Status: NOT YET IMPLEMENTED

  Current: R=F444W, G=F277W, B=avg(F115W,F150W) with Lupton RGB stretch
  COWLS II: "images produced combining the four filters" — credits Kaija
  Virolainen for rendering. Two inspection combos used:
    - F115W/F150W/F444W
    - F115W/F277W/F444W

  The COWLS images show vivid colors: orange/yellow lenses, blue/green arcs,
  rich background galaxy colors. Our current rendering produces acceptable
  but less vivid results.

  Possible improvements:
    a) Try the two COWLS inspection combos as alternative RGB mappings
    b) Tune Lupton stretch/Q parameters for better dynamic range
    c) Try per-channel percentile scaling (SDSS-style)
    d) Add noise-aware background subtraction before RGB (cleaner sky = blacker)
    e) Investigate Lupton+ vs. alternative methods (log, asinh per-channel)

  Impact: Medium (visual quality only, doesn't affect training data)


  UPGRADE 2: IMAGE SCALE / FIELD OF VIEW
  ───────────────────────────────────────
  Status: NOT YET IMPLEMENTED

  Current: 224x224 px at 30mas = 6.72" x 6.72" FoV
  COWLS II: 18.9" x 18.9" panels = 630x630 px at 30mas

  The COWLS images show much more context around the lens, including the
  full extent of large Einstein radius systems and surrounding galaxies.
  Our 224x224 cutouts may clip the outer structure of larger systems.

  Implementation:
    a) Run prep_mosaic.py with --size 630 (or similar)
    b) Run prep_sources.py for new size
    c) Run simulate_v3.py with --size 630
    d) Requires ~6.3x more background data per patch

  Impact: High for visual quality, moderate for classifier training
  Note: May require larger source stamps (currently 65x65 = 1.95")


  UPGRADE 3: PSF DECONVOLUTION OF SOURCE STAMPS
  ──────────────────────────────────────────────
  Status: NOT YET IMPLEMENTED

  Currently source galaxy stamps include the JWST PSF convolution from the
  mosaic imaging. When used as INTERPOL sources, lenstronomy convolves the
  lensed image with the PSF again, causing mild double-convolution.

  Fix: Apply Richardson-Lucy or Wiener deconvolution to the extracted stamps
  using our empirical PSF before normalizing. This removes the original PSF
  so that lenstronomy's single convolution gives the correct final result.

  Implementation:
    - scipy.signal.fftconvolve-based Richardson-Lucy (15-20 iterations)
    - Use per-band psf_median.npy as deconvolution kernel
    - Apply before normalization in prep_sources.py
    - Validate by comparing PSF width in final images

  Impact: Low-Medium (effect is modest for resolved galaxies)


  UPGRADE 4: MULTI-COMPONENT LENS MASS MODELS
  ────────────────────────────────────────────
  Status: NOT YET IMPLEMENTED

  Current: SIE + external shear (single component)
  Real lenses often have:
    - Multiple mass components (main lens + satellite/perturber)
    - Substructure (dark matter subhalos causing flux ratio anomalies)
    - Line-of-sight structure (secondary deflectors)

  COWLS II Table 1 shows some systems require complex mass models for
  accurate reproduction. Adding multi-component models would produce
  more diverse arc morphologies (asymmetric, broken arcs).

  Impact: Medium (more diverse training examples)

  ────────────────────────────────────────

  See Step 14 below.

STEP 14 — REALISTIC LENS LIGHT (INTERPOL ELLIPTICAL GALAXY STAMPS)
================================================================================
Date: March 12, 2026

PROBLEM
-------
Lens galaxies rendered with single Sersic ellipse profiles look obviously
artificial — perfectly smooth, symmetric light distributions that lack the
natural substructure of real elliptical galaxies.

SOLUTION
--------
1. Created prep_lenses.py to extract real elliptical galaxy stamps from
   the DR0.5 mosaics, similar to prep_sources.py but selecting compact/
   elliptical morphology:
   - Detects in F444W (25-sigma, ellipticals brightest in NIR)
   - Concentration filter: 0.45 < C < 0.75 (resolved ellipticals, not stars)
   - Mid-radius flux check to reject point sources
   - Cosine edge taper (10px width) to avoid hard stamp boundary
   - Larger stamps: 101x101 = 3.03" (vs 65x65 for sources)
   - Each stamp normalized to sum=1 per band

2. Modified simulate_v3.py to use INTERPOL model for lens light:
   - Loads lens stamps at startup (like source stamps)
   - Per-band rendering: LightModel(['INTERPOL']) with lens stamp
   - Random rotation (phi_G) and horizontal flip for diversity
   - Amplitude calibration: render with amp=1, measure total, rescale
   - --sersic flag forces both source and lens to Sersic (for comparison)

3. Fixed Poisson noise overflow:
   - INTERPOL lens light can produce very large pixel values in sim units
   - Added NaN/inf sanitization before Poisson sampling
   - Gaussian approximation for electron counts > 1e8 (Poisson→Normal)
