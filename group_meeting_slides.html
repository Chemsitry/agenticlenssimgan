v8 changed the game: each sample is one real COSMOS-Web cutout with only the lensed arcs simulated. Non-lensed sims are bit-identical to real data — so "is it realistic?" collapses to a single question: do the injected arcs look real?

What a discriminator would key on — six predictions from reading the code

Each is a fixed value or modeling choice in simulate_v8.py — independently testable, independently fixable. Bars = guessed visibility to a 4-band patch discriminator.

1 · Every lens has the same shape

SIE ellipticity fixed at (0.05, 0.02), shear at (0.02, 0.01) — one near-circular mass family generates every arc.

visibility
simulate_v8.py · kwargs_lens

2 · Arc/lens flux ratio is a constant

Total arc flux = lens peak proxy × 50 × 0.25, every system. COWLS lens/source magnitudes show the real ratio varies by orders of magnitude.

visibility
simulate_v8.py · amp anchoring

3 · Mass at (0,0), light wherever it is

The mass model is pinned to the image center; the real galaxy is only near center. Arcs can curve around a point offset from the visible lens.

visibility
simulate_v8.py · center_x/y = 0

4 · A noise seam at the arc footprint

Arcs get pure Poisson noise on injected photons; the surrounding mosaic noise is drizzle-correlated + read noise. The texture changes exactly where the sim content is.

visibility
simulate_v8.py · sim_to_elec / Poisson

5 · Arcs identical in all 4 bands

VELA stamps are normalized per band, so one morphology × one analytic SED. Real star-forming sources are clumpier and bluer in blue bands.

visibility
prep_vela_v7.py · per-band sum=1

6 · θE blind to lens brightness (v9 fixes this)

v8 draws σv independently of the scene — a dwarf can get 320 km/s. v9 derives σv from the cutout's own photometry (+31 measured DESI σv). Built-in experiment: D should find v9 harder.

The plan: dataset design is the experiment

The trap to avoid

Real sky has ~no strong lenses, and in v8 only lensed images contain sim pixels. So lensed sims vs random real cutouts trains a lens detector — ~100% accuracy, zero insight into realism.

The primary experiment

v9 lensed sims vs real lens cutouts at the 440 COWLS positions (same mosaics, same depth). Both piles have lens + arcs → D must judge whether the arcs look real. Control: a real-vs-real null test that must score ~50%, or our own pipeline is biased.

Scene pool: the bottleneck, and the fix already in the repo

v8 ships 46 scenes (caps datasets at 92 images). Nate's v9 catalogs already list 1,015 scene galaxies + 1,236 JADES ellipticals — the coordinates are in git; we extract the pixels.

4 / 4 · risks & asks

Where this can go wrong — and what we do about it

RiskHow it bitesMitigation
Scene memorization Any network memorizes a small background pool; accuracy becomes fiction. Split by scene ID (never random), grow pool 46 → 242 → 1,015+, arc-centered crops.
Only ~440 real lenses, ever Nature's limit, not Nate's — deep nets overfit at N≈10². Small D, patch-level training (~80 patches/image), 8× dihedral aug, k-fold CV, frozen-feature linear probes.
Field signature confound UDS/GDN/CEERS scenes differ in depth/PSF; D classifies field, not realism. CEERS lacks F444W. Primary comparison COSMOS-only (COWLS is COSMOS); per-field normalization; other fields for variety/controls only.
D wins on something boring A trivial tell (e.g. fixed flux ratio) saturates D before subtle physics is probed. That's still feedback — fix it, regenerate, retrain. Null test gates every run; PCA baseline catches "linear & boring" early.
The gap isn't per-image If the mismatch lives in population statistics (counts, clustering), no per-image D can see it. Parameter-correlation readout covers distributions; if all else fails, escalate — that's a finding too.
