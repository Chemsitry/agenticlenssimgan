Six differences it would probably find

Nothing is trained yet — each of these is a fixed number or shortcut in the simulator code that real data doesn't share. Each one is easy to test, and easy to fix, on its own.

1 Every simulated lens has the same shape

The code uses one fixed ellipticity and tilt for every lens, so every arc pattern comes from the same nearly-round mass. Real lenses come in all shapes — see the figure: changing these knobs changes the arcs a lot.

how easy to spot (our guess)

2 The arcs always have the same relative brightness

Arc brightness is set to exactly 25% of the lens galaxy's, every time. In real lenses this ratio varies enormously.

how easy to spot

3 The arcs' noise looks different from the sky around them

Real JWST noise is slightly smeared between neighboring pixels (an artifact of how images are stacked). The simulated arcs get perfectly independent pixel noise — the texture changes exactly where the simulated part begins.

how easy to spot

4 Arcs bend around the image center, not around the galaxy

The invisible mass is pinned to the exact center of the image; the visible galaxy is only near the center. The arcs can curve around a slightly wrong point.

how easy to spot

5 The arc looks identical in every color band

One shape is reused in all four wavelength bands, just scaled in brightness. Real young galaxies look clumpier and bluer in the blue bands (right figure).

how easy to spot

6 Arc size ignores how big the lens galaxy looks (v9 fixed this)

In v8 a tiny faint galaxy could get a huge arc ring. Nate's v9 ties the mass to the galaxy's measured brightness — which gives us a built-in experiment: the network should find v9 harder to catch than v8. If it doesn't, something's off.

how easy to spot

How we set up a fair test

The trap

Random sky almost never contains a lens. Compare sims against random sky, and the network just learns "has arcs = fake". It scores ~100% and teaches us nothing.

The fix

Compare against real lenses. COSMOS-Web contains 440 known real lens systems (the COWLS catalog). Now both piles show a galaxy with arcs — the only way to score well is to judge whether the arcs look real.

The honesty check

We also run real vs real through the same pipeline. A fair setup must score ~50% (a coin flip) there. If it doesn't, our pipeline is biased and no result can be trusted.

One problem: the simulator only has 46 backgrounds

Every sim is built on one of just 46 real galaxy cutouts — a network could simply memorize them. Good news: Nate's v9 catalogs already list 1,015 suitable galaxies, and 242 of them sit in data we already have on disk.

What can go wrong & what we ask

RiskWhat we do about it
It memorizes the backgrounds.
Like a student memorizing answers instead of learning.		 Never test on a background galaxy it saw in training, and grow the pool 46 → 242 → 1,000+.
Only ~440 real lenses exist.
That's nature's limit — small data for a neural network.		 Keep the network tiny, judge small image patches (hundreds per image) instead of whole images, and cross-check every result on multiple data splits.
It wins on something boring.
e.g. it catches the fixed 25% brightness immediately and stops looking deeper.		 That's still a result — fix it, regenerate, train again. Each round peels off one layer.
Mixing telescope surveys.
Galaxies from other JWST surveys look different (depth, blur) — the network could detect the survey, not the realism.		 The main test stays within COSMOS-Web only; other surveys are used only to add training variety.

Asks for Nate

• A small flag to generate lensed images only (the current setup caps a dataset at 92 images)
• Sanity-check our background-galaxy cutouts against your v9 lists
• Longer term: run your galaxy selection over the full survey → thousands of backgrounds
• Which of the six predictions do you already suspect? It helps us prioritize.

What we start now

• The two cut-out scripts (backgrounds + real lenses)
• The honesty check and the simple statistics baseline
• Two checks that need no images at all: compare the simulated arc brightnesses and arc sizes against the real COWLS catalog numbers

Bottom line: the network is the cheap part — choosing the right comparison data is the science, and the catalogs that fix it are already in the repo.
